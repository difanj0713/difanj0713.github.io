Agent-SIREN

Detecting Harmful Agent Trajectories from LLM Internal Representations

Difan Jiao, Ashton Anderson

Code Model pip install llm-siren

The idea

An agent acts through tools, so its mistakes cost more than a chatbot's. But a trajectory can be unsafe in two quite different ways. Harmful content is stated outright, which is what content moderation was built to catch. Unsafe tool use turns on whether an action is consistent with the interaction that produced it: the right vendor, the right amount, the wrong authorisation. No single message in such a trajectory reads as harmful on its own.

To separate the two we built matched pairs. For tool use, two trajectories with byte‑identical messages and byte‑identical final actions, differing only in the schema of the tool that action calls. For content, two rollouts of the same scenario with the same toolkit, differing in what the agent says.

What it showed

On those pairs, the leading open guards' own verdicts separate harmful content well above chance and sit at chance on unsafe tool use. Reading the same models internally tells a different story: a linear direction estimated out of fold orders the tool‑use pairs correctly up to 0.94 inside the guards and 0.98 inside the general‑purpose backbones they were tuned from, peaking in the middle layers and falling off toward the final one, which is exactly the state a generative guard reads its label from.

The two forms of risk also follow near‑orthogonal internal directions, so supervision for one should not be expected to deliver the other. That is what motivates the guard: one linear score can carry both, and it does so from different coordinates.

The resulting readout is a single linear probe on one validation‑selected hidden state of a frozen backbone: 2,561 trainable parameters. Across six trajectory‑safety benchmarks, held out one at a time, it reached the highest mean macro‑F1 of the open guard checkpoints we evaluated. Under matched training data it is on par with fully fine‑tuning the same backbone, and because it reads representations rather than replacing them, fitting it on top of that fine‑tune improves the result again.
