The phenomenon

01

Asking a model for a judgment means reading the very end of a long computation.

Most of what we want out of a language model is not an essay. It is a judgment. Is this safe. Is this document the one. Which category applies. Should this action be allowed.

There are two standard ways to get one: read the model's final layer, or make the model say the answer out loud. Those are the same move. Both take a computation that ran through dozens of layers and read it at the last one.

02

The judgment is usually there before it is spoken.

This is the part that keeps surprising us. Fit the simplest reader there is, a straight line, to what the model is holding partway through, and it recovers judgments the model's own answer never expresses. We have now watched it happen in four settings, on four different kinds of input.

The model did the work. The last step is just narrow, and the last step was the only part anyone was reading.

03

What falls out is sparse, sits mid‑stack, and is almost free to pick up.

Three things hold every time. The signal is linear, so a straight line is enough to read it. It is concentrated, carried by a small fraction of the coordinates. And it is strongest in the middle of the network, above the depth everything gets read from.

So recovering it is not a research project. It is one forward pass and a set of weights small enough to send in an email.

So when does this work?

The recipe does not care what the model is for. It cares that the answer is compact. Whenever what you want out of a model is a label, a score, a ranking or an embedding, rather than open-ended text, you can read it out instead of generating it.

  • Read, do not generate. The target is a concept to be recovered, not a passage to be written.
  • The concept is already in there. Probing locates what pretraining put in the model. It does not put it there.
  • The incumbent reads the end. A fine‑tuned head, a generated verdict, a final‑layer embedding. That is the bottleneck worth attacking.

And because a read is a number rather than a word, it hands you what a generated verdict cannot: a threshold you can move after the fact, a reading at every point in a stream, and the option to stop the forward pass early.

01 · Activations

Every token lights up every layer.

For a single input sentence, record the activation of every internal unit, at every layer, at every token position. This block is what one forward pass leaves behind.

02 · Pooling

Collapse the sentence into a vector.

Pool over token positions, keeping for each unit the response that matters most anywhere in the sentence. The token axis disappears and each layer is left with one vector.

03 · Probing

Ask each layer, one at a time.

Fit a sparse linear probe on each layer independently. Under an L1 penalty, the magnitude of the learned weights is a usable statement of how much each unit contributed. That is its saliency.

04 · Sparsifying

Most units are not about the task.

Keep the smallest set of units carrying the bulk of each layer's decision and drop the rest. Roughly three quarters of them go. The accuracy does not go with them.

05 · Integrating

Depth is a feature, not a stage.

The survivors are carried forward and gathered across layers, so a decision taken at any depth can draw on everything the network computed below it.

06 · Readout

One head. One forward pass. No decoding.

What comes out is a classifier that reads the model's own state instead of waiting for its output. It fits in kilobytes, it trains on a laptop, and it answers without generating a single token.
